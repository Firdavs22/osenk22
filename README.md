# Осень Кусна — сайт заказов, Telegram-бот и веб-админка

Готовый проект для одного магазина. Python + aiogram + FastAPI + SQLite. Запуск на VPS через systemd, **без Docker и без отдельного сервера базы данных**.

Покупатель заказывает на сайте или в Telegram. Сотрудник управляет магазином в браузере, в том числе с телефона.

Обновление существующего магазина, приёмка и ограничения новой витрины: **[STORE_LAUNCH.md](STORE_LAUNCH.md)**. Главная `/` теперь публичная, админка — `/admin`.

Дополнительные инструкции: [переменные .env](ENV.md), [GitHub и обновления VPS](GITHUB_VPS.md), [подключение iiko](IIKO.md).

## Что реализовано

- Категории, карточки с фотографией, названием, ценой, составом, описанием, весом и наличием. Массовая публикация и скрытие блюд.
- Обновление внешнего меню iiko по расписанию: цены, группы, вес и фото (Selectel CDN/Storage), с сохранением ручных составов и собственных фотографий.
- Корзина с изменением количества и удалением позиций. Корзина и этап оформления сохраняются в SQLite.
- Доставка или самовывоз, имя, телефон, адрес, комментарий и финальное подтверждение.
- Минимальная сумма, фиксированная стоимость доставки, порог бесплатной доставки.
- Оплата при получении; подготовлено подключение Т-Банка через админку. Реальный терминал и кассу необходимо настроить и проверить.
- Повторное подтверждение не дублирует заказ. Изменения цены, наличия, корзины или условий требуют нового подтверждения.
- Заказ сохраняет названия и цены на момент покупки, независимо от последующего редактирования меню.
- Уведомления покупателю и Telegram-администраторам. Очередь с повторными попытками переживает перезапуск.
- Веб-админка: обзор, товары, категории, заказы, статусы, условия работы, очередь уведомлений, бренд, слайды и интеграции.
- Вход по паролю, хеширование scrypt, CSRF, ограничение попыток входа, проверка загруженных изображений.
- Скрипт установки, сервисы systemd, пример Nginx, ежедневное резервное копирование базы и фото.
- **5 демонстрационных товаров** с ценами, составом и весом. Фотографии нужно загрузить самостоятельно; вместо них показаны заглушки.

## 1. Что понадобится

- VPS с Ubuntu 24.04 или Debian 12+, Python 3.11+ и доступом к Telegram API и PyPI. Практичный старт: 1 CPU, 1 ГБ RAM, диск от 10 ГБ.
- Токен бота: в Telegram откройте официальный **@BotFather**, отправьте `/newbot`, задайте имя и username.
- Ваш числовой Telegram ID, например полученный у **@userinfobot**. Для уведомлений нужны ID пользователей, а не `@username`.
- Домен и HTTPS нужны для публичного сайта и онлайн-оплаты. Для локального теста можно использовать HTTP с COOKIE_SECURE=false.

Бот использует long polling: входящий порт или webhook для него не требуется. На один токен запускайте только один процесс бота.

## 2. Установка на VPS

Команды ниже рассчитаны на **первую установку**. Архив содержит верхнюю папку `sushi-bot/`. Замените `USER` и `SERVER_IP` своими значениями.

С компьютера:

```bash
scp sushi-bot.zip USER@SERVER_IP:/tmp/sushi-bot.zip
ssh USER@SERVER_IP
```

На сервере:

```bash
sudo apt-get update
sudo apt-get install -y unzip
sudo unzip /tmp/sushi-bot.zip -d /opt
cd /opt/sushi-bot
sudo bash deploy/install.sh
sudo -u sushi .venv/bin/python -m app.manage setup
sudo -u sushi .venv/bin/python -m app.manage seed
sudo systemctl enable --now sushi-web sushi-bot sushi-backup.timer
```

`setup` интерактивно запросит токен, ID администраторов, логин и пароль веб-панели. Ввод токена и пароля скрыт. Секреты сохраняются в `.env`, пароль — только в виде хеша. Скрипт не изменяет существующие товары и заказы.

`seed` добавит примеры, только если каталог пуст: Филадельфия, Калифорния, Запечённый лосось, Сет на двоих, Суши с лососем. Чтобы начать с пустым меню, пропустите эту команду.

**Каждый администратор должен открыть созданного бота и отправить `/start`.** Иначе Telegram не позволит боту первым написать ему.

Проверьте запуск:

```bash
sudo systemctl status sushi-web sushi-bot --no-pager
curl http://127.0.0.1:8000/health
sudo -u sushi .venv/bin/python -m app.manage check
```

`/health` проверяет доступность веб-приложения и базы, но не соединение Telegram. Бот проверяется отдельным `/start` и журналом сервиса.

## 3. Открыть веб-админку

### Вариант A: без домена, через SSH-туннель

На своём компьютере выполните и оставьте окно открытым:

```bash
ssh -N -L 8000:127.0.0.1:8000 USER@SERVER_IP
```

Откройте **http://127.0.0.1:8000**. Войдите логином и паролем из `setup`. В `.env` оставьте `COOKIE_SECURE=false`: транспорт до VPS защищён SSH, браузер обращается к localhost по HTTP.

### Вариант B: домен и HTTPS, удобно с телефона

1. Направьте A-запись `admin.your-domain.ru` на IP VPS. Если используете AAAA, проверьте доступность VPS по IPv6.
2. Разрешите входящие TCP 80/443 в сетевом экране VPS, сохранив доступ SSH. Порт 8000 наружу открывать не нужно.
3. Установите Nginx и Certbot:

```bash
sudo apt-get install -y nginx certbot python3-certbot-nginx
sudo cp deploy/nginx.conf /etc/nginx/sites-available/sushi-admin
sudo nano /etc/nginx/sites-available/sushi-admin
```

Замените `admin.example.com` своим доменом, затем выполните:

```bash
sudo ln -s /etc/nginx/sites-available/sushi-admin /etc/nginx/sites-enabled/sushi-admin
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d admin.your-domain.ru --redirect
sudo nano /opt/sushi-bot/.env
```

В `.env` установите `COOKIE_SECURE=true`, сохраните и перезапустите веб-сервис:

```bash
sudo systemctl restart sushi-web
```

После выдачи сертификата открывайте **https://admin.your-domain.ru/admin**. При `COOKIE_SECURE=true` авторизация по обычному HTTP не работает. Веб-сервис слушает только `127.0.0.1`; заголовки прокси принимает только от локального Nginx.

## 4. Первый пробный заказ

1. В админке откройте **Настройки**. Укажите телефон магазина, адрес самовывоза, часы работы и условия доставки. Включите **Принимать заказы**, сохраните.
2. Откройте **Меню и товары**. Проверьте демонстрационные карточки, загрузите свои фото или добавьте свои блюда. Цены и состав примеров условные.
3. Отправьте боту `/start`, выберите «Роллы» → «Филадельфия» → «В корзину».
4. Откройте корзину и оформите заказ: получение → имя → телефон → адрес для доставки → комментарий → подтверждение.
5. Убедитесь, что бот прислал покупателю номер заказа, а администратору — уведомление с деталями.
6. В веб-панели откройте **Заказы** → заказ. Переведите его в «Принят», «Готовится», «Готов / передан курьеру», «Выполнен». Покупатель получит сообщения.
7. Пробный заказ можно перевести в «Отменён» до завершения; он останется в истории.

По умолчанию: минимальная сумма товаров 500 ₽, доставка 200 ₽, бесплатно от 2 000 ₽. Самовывоз бесплатный. Значение `0` в пороге бесплатной доставки отключает этот порог. Минимальная сумма относится к товарам, без доставки, и действует также для самовывоза.

Команды покупателя: `/menu`, `/orders` (последние 5 заказов), `/cancel` (отменить оформление, сохранив корзину), `/privacy`, `/id`.

Чтобы убрать блюдо из продажи, нажмите **Скрыть из меню**. Для удаления его из старой корзины покупатель использует кнопку `✕`. Скрытый товар нельзя заказать. Категории можно создавать и переименовывать.

## 5. Обслуживание

Журналы и перезапуск:

```bash
sudo journalctl -u sushi-bot -n 100 --no-pager
sudo journalctl -u sushi-web -n 100 --no-pager
sudo systemctl restart sushi-bot sushi-web
```

После изменения `.env` перезапустите оба сервиса. Обычные изменения в веб-админке применяются сразу.

Смена пароля: выполните `.venv/bin/python -m app.manage password`, вставьте полученный хеш в `ADMIN_PASSWORD_HASH` файла `.env` и перезапустите веб-сервис. Старые сессии перестанут работать. Полную повторную настройку можно выполнить через `setup`; она также меняет секрет сессии.

### Резервные копии

Таймер ежедневно запускается около 04:15 по времени сервера. Архив содержит согласованную копию SQLite, фотографии и ключ интеграций (если создан); **`.env` в архив не входит**.

```bash
sudo systemctl list-timers sushi-backup.timer
sudo -u sushi .venv/bin/python -m app.manage backup
```

Архивы находятся в `/opt/sushi-bot/data/backups/`. Копируйте их за пределы VPS. Хранение не ограничено автоматически: следите за местом и удаляйте ненужные копии после проверки внешнего резервирования. `.env` сохраните отдельно в защищённом месте.

Восстановление:

1. Остановите `sushi-bot`, `sushi-web`, `sushi-backup.timer` и `sushi-backup.service`.
2. Переименуйте существующую папку `data` в `data-before-restore-ДАТА`, сохранив её для отката.
3. Создайте новую `/opt/sushi-bot/data` и распакуйте в неё резервный архив. `shop.sqlite3` должен лежать непосредственно в `data`, фото — в `data/media`.
4. Назначьте папке и содержимому владельца `sushi:sushi`, права каталога `700`. Верните `.env`, если переносите проект на новый VPS.
5. Запустите `.venv/bin/python -m app.manage check` от пользователя `sushi`, затем включите сервисы и таймер.

Не копируйте только файл рабочей SQLite при включённом боте: часть данных может находиться в WAL. Используйте команду `backup`.

### Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Бот молчит | Токен, `systemctl status sushi-bot`, журнал, доступ VPS к `api.telegram.org` |
| Telegram сообщает Conflict | Этот же токен запущен где-то ещё; оставьте один процесс |
| Администратор не получает заказы | Числовой `ADMIN_IDS`, `/start` от каждого админа, очередь «Уведомления» |
| Магазин закрыт | Флажок «Принимать заказы» в настройках |
| Не проходит вход по HTTP | `COOKIE_SECURE=true` требует HTTPS; для SSH-туннеля используйте false |
| 502 от Nginx | Статус `sushi-web`, журнал, `curl http://127.0.0.1:8000/health` |
| После изменения товара заказ не подтверждается | Это защита от старых цен/состава; заново оформить через корзину |
| Кнопка подтверждения нажата дважды | Бот вернёт тот же номер; второй заказ не создаётся |

## 6. Локальный запуск и тесты

### Быстрая проверка на Windows

Дважды щёлкните `START-WINDOWS.cmd` (нужен установленный Python 3.11+). При первом запуске он установит зависимости, запросит токен @BotFather, числовой Telegram ID администраторов, логин и пароль веб-панели. Затем добавит 5 примеров, если каталог пуст, и запустит бота с админкой.

Админка откроется на `http://127.0.0.1:8000`. Укажите контакты магазина в настройках и включите **Принимать заказы**, затем отправьте созданному боту `/start` и пройдите заказ. Оставьте окно запуска открытым. Для остановки нажмите Ctrl+C. Повторный запуск использует сохранённый `.env` и базу. Этот бот использует базу `data/` проекта; ранее открытая демонстрация на порту 8765 имеет отдельные данные.

Журналы локального запуска: `data/local-web.log` и `data/local-bot.log`. При занятом порте запустите `python start_local.py --port 8001`. Для повторной настройки используйте `python -m app.manage setup` в виртуальном окружении, пока локальный запуск остановлен.

### Запуск вручную

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock.txt
python -m app.manage setup
python -m app.manage seed
uvicorn app.admin:app --host 127.0.0.1 --port 8000
```

Во втором терминале, в том же виртуальном окружении:

```bash
python -m app.bot
```

Windows PowerShell: создайте окружение командой `python -m venv .venv` и вместо активации вызывайте `.venv\Scripts\python.exe` / `.venv\Scripts\uvicorn.exe` напрямую. Docker не требуется ни локально, ни на VPS.

Автотесты используют временную базу и имитацию Telegram API; настоящий токен не нужен:

```bash
python -m pip install -r requirements.lock.txt
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
```

`requirements.lock.txt` фиксирует проверенные версии. `requirements.txt` задаёт допустимые диапазоны для планового обновления зависимостей; после обновления запускайте тесты и сохраняйте новый lock-файл.

## Границы текущей версии

- Один магазин, один веб-аккаунт администратора, несколько Telegram-получателей уведомлений.
- Один процесс бота и один веб-worker, SQLite на локальном диске. Горизонтальное масштабирование не предусмотрено.
- Наличие переключается вручную. Учёта остатков по порциям и интеграций с кассой/CRM нет.
- Часы работы информационные: приём заказов открывается и закрывается вручную.
- Доставка рассчитывается фиксированно; адрес, зона и время подтверждаются сотрудником. Онлайн-карт и геокодирования нет.
- Смена символа валюты не конвертирует цены. Онлайн-оплата поддерживает только рубли; настройки и ограничения описаны в STORE_LAUNCH.md.
- Заказы, контакты, черновики и очередь уведомлений сохраняются до обслуживания базы; автоматическая политика удаления не настроена. Контакт магазина виден через `/privacy`.
- Уведомления доставляются с повторными попытками. При аварии после отправки, но до записи результата, возможно повторное сообщение; сам заказ при этом не дублируется.
- Старые фотографии ручной загрузки сохраняются; заменённые фотографии фонового импорта iiko удаляются, если больше не используются. Со временем может понадобиться очистка неиспользуемых фото.
- Реальные подключение к Telegram и установка на конкретный VPS требуют вашего токена и доступа к серверу. Они не входят в локальную автоматическую проверку.

## Устройство проекта и документация

`app/bot.py` — Telegram; `app/admin.py` — веб; `app/db.py` — данные и логика заказов; `app/templates` и `app/static` — интерфейс; `app/manage.py` — настройка и резервирование; `deploy` — VPS; `tests` — проверки.

Использованные официальные справочники: [aiogram — long polling](https://docs.aiogram.dev/en/v3.17.0/dispatcher/long_polling.html), [FastAPI — шаблоны](https://fastapi.tiangolo.com/advanced/templates/), [FastAPI — формы и файлы](https://fastapi.tiangolo.com/tutorial/request-forms-and-files/).
