# Витрина «Осень Кусна»: запуск и приёмка

Эта версия добавляет сайт к существующему боту. Главная `/` теперь публичная; панель находится в `/admin`, вход — `/admin/login`. Старая ссылка `/login` перенаправляет на новый вход. Старые закладки `/products`, `/orders` нужно заменить на `/admin/products`, `/admin/orders`.

## Что работает

- Единый каталог для сайта и Telegram: категории, фото, состав, описание, вес, наличие; теги и поиск на сайте.
- «Заказать» сразу добавляет блюдо, «Подробнее» открывает модальное окно. Сохранённая на сервере корзина доступна по защищённой cookie браузера. Очистка cookie или истечение сессии потребует новой корзины.
- Доставка/самовывоз, контакты, комментарий, итог с сервера, защита от повторного оформления и изменения цены. Страница заказа доступна по случайной секретной ссылке.
- Админка: логотип, название, описание, условия доставки, реквизиты, тексты документов, статичный первый экран либо карусель до 12 слайдов с кнопками. Карусель переключается вручную.
- Общие заказы с указанием источника и состояния оплаты. Telegram-уведомления о заказах сайта отправляются администраторам; сообщения покупателю сайта не отправляются, статус виден по его ссылке.
- Т-Банк: Init, проверка GetState, подписанный webhook, восстановление неопределённого результата через CheckOrder, чек предоплаты ФФД 1.2. Карта/СБП доступны в соответствии с настройкой платёжной формы терминала.
- iiko: новая авторизация v2, чтение организаций/терминалов/типов оплаты/номенклатуры, импорт внешнего меню с предпросмотром, сопоставление UUID, очередь отправки принятого заказа, проверка результата по постоянному UUID. Стоп-лист проверяется iiko при создании.

## Граница проверки

Локально проверены автоматические тесты с изолированной SQLite, ответы интеграций имитируются. В браузере пройден заказ с доставкой, проверены модальное окно, теги, добавление в корзину, отображение заказа в админке, мобильная корзина и самовывоз. Это не является подтверждением реального списания, выдачи фискального чека или приёма заказа вашей кассой iiko.

Нужны ваши данные и контрольный заказ до включения онлайн-оплаты покупателям. Никаких встроенных рабочих ключей в архиве нет. На действующий VPS эта версия автоматически не устанавливается.

## Обновление существующего VPS

Сначала проверьте версию на отдельном тестовом экземпляре с копией базы. У копии должны быть собственный DATA_DIR, свой адрес/порт, отключены Telegram, iiko и Т-Банк; не запускайте два polling-процесса с одним токеном. Не копируйте действующие ключи в публичный тестовый стенд. Доступ к копии персональных данных ограничьте.

На рабочем сервере выберите время без заказов, выключите приём в настройках, дождитесь завершения всех незаконченных оплат и запишите текущий Git SHA:

```bash
cd /opt/sushi-bot
git status --short
git rev-parse HEAD
sudo systemctl stop sushi-bot sushi-web
sudo -u sushi .venv/bin/python -m app.manage backup
git fetch origin
```

Сохраните показанный путь резервной копии **вне VPS** вместе с защищённой копией `.env`. До изменения кода убедитесь, что архив создан. Если резервное копирование не удалось, остановитесь и запустите прежние сервисы.

После приёмки и слияния изменений в `main`:

```bash
git merge --ff-only origin/main
.venv/bin/python -m pip install -r requirements.lock.txt
sudo -u sushi .venv/bin/python -m app.manage init
sudo systemctl start sushi-web sushi-bot
sudo systemctl status sushi-web sushi-bot --no-pager
curl --fail http://127.0.0.1:8000/health
```

Команды выполняйте по очереди. При ошибке не продолжайте до её устранения. Не выполняйте `setup` повторно ради обновления: текущие `.env`, пароль и каталог сохраняются. Миграция добавляет таблицы и колонки и не пересоздаёт существующие заказы. Nginx продолжает проксировать весь домен на порт 8000. Для HTTPS оставьте `COOKIE_SECURE=true`.

После обновления:

- `https://app.osenkusna.ru/` — витрина;
- `https://app.osenkusna.ru/admin` — админка с прежними логином и паролем;
- `/admin/appearance` — оформление;
- `/admin/integrations` — подключения.

Если нужно проверить ветку до слияния, используйте её только на тестовом экземпляре: `git switch --track origin/feature/online-store`. Рабочие заказы не переводите на ветку без приёмки.

### Восстановление

Остановите оба сервиса. Сохраните отдельную копию текущей базы, чтобы не потерять заказы после обновления. Верните записанный предыдущий commit и его зависимости. Старый код не поддерживает новые web-заказы: восстановите согласованную предобновлённую базу и фото из резервной копии, а поступившие после неё заказы/платежи сначала сверяйте вручную. Не удаляйте новые данные без этой сверки. Из новой резервной копии восстанавливаются `shop.sqlite3`, `media/` и `integrations.key`; `.env` хранится отдельно. Ключ шифрования и база должны соответствовать друг другу.

## Подготовить реальные данные

1. Импортировать внешнее меню iiko либо заполнить каталог вручную. Проверить фото, составы/аллергены, цены и вес и опубликовать карточки. Примеры не являются настоящим меню.
2. В «Настройках» проверить телефон, адрес, режим работы, минимум и доставку. Время работы информационное; приём включается вручную. Геозона и время доставки подтверждаются сотрудником, карты и маршрутизации в этой версии нет.
3. В «Оформлении» загрузить логотип, акции и действующие документы продавца. Фотографии JPEG/PNG/WebP до 5 МБ; после обработки — JPEG, прозрачность не сохраняется. Ссылка кнопки акции: `#catalog` или `#category-ID`.
4. В «Интеграциях» настроить Telegram и проверить токен. Получатели должны начать диалог с ботом или добавить его в указанный чат. Проверка getMe не отправляет сообщений; получение уведомления проверяется контрольным заказом.
5. Оформить заказ с сайта и через Telegram, сверить состав/сумму/адрес, провести статусы до «Выполнен». Проверить перезапуск сервисов и резервную копию.

## Т-Банк

Внесите TerminalKey, пароль терминала и публичный URL `https://app.osenkusna.ru` в админке. Начните с тестового терминала, выданного банком. Секретные поля не заполняются сохранёнными значениями; пустое поле означает «оставить прежний пароль».

Укажите систему налогообложения и НДС товаров/доставки согласно настройкам вашей кассы. В данной версии применяется единая ставка для всех товаров. Перед включением настройте выдачу чека предоплаты и закрывающего чека через свою кассу/iiko с вашим интегратором. Автоматическая отправка закрывающего чека и запуск возврата из этой админки не реализованы; возврат производится в банке, завершающий чек — в кассе. Не включайте подтверждение готовности кассы до фактической настройки.

Webhook: `https://app.osenkusna.ru/api/payments/tbank/webhook`, HTTP POST без Basic Auth и без ограничения только по вашему IP. Токен уведомления проверяется, изменение оплаты выполняется после независимого GetState. Возврат покупателя по SuccessURL не считается оплатой. У существующего платежа сохраняется зашифрованная копия использованных настроек: их смена не переключает старый платёж на другой терминал.

Проверка: успешная оплата, отказ/закрытие окна, повторное уведомление, недоступность API, восстановление после перезапуска, сверка суммы и заказа, возврат через кабинет банка. Зафиксируйте OrderId/PaymentId и наличие чека. При неизвестном результате Init новый платёж автоматически не создаётся; оператор сверяет старый в банке. Ссылка оплаты живёт 30 минут, автоматическая частая проверка ограничена числом попыток; в админке есть «Проверить». Успешные платежи далее опрашиваются раз в час для выявления возвратов.

Отмена заказа в админке **не отменяет платёж**. Если деньги пришли после отмены, сотрудник должен сверить операцию и оформить возврат. Часть платёжных состояний может потребовать ручной проверки в кабинете банка.

## iiko

См. [IIKO.md](IIKO.md): доступы, ограничения и контрольная передача. Для ресторана без API-доступов блок можно заполнить позже и оставить выключенным. Продажи с оплатой при получении работают независимо от iiko.

## Эксплуатация

Один процесс `sushi-web`, один `sushi-bot`; SQLite предназначена для одного магазина на одном сервере. Очереди интеграций выполняются внутри веб-сервиса, поэтому он должен постоянно работать. Для масштабирования на несколько серверов понадобится отдельная база/очередь и блокировки задач.

Секреты интеграций зашифрованы Fernet в SQLite, ключ — `DATA_DIR/integrations.key` с правами 0600 на Linux. Не переносите его в GitHub. Резервные копии включают ключ, поэтому сами архивы содержат доступ к секретам: храните их в защищённом месте. `.env` по-прежнему содержит учётные данные админки и начальные настройки Telegram. Изменения Telegram в админке имеют приоритет над `.env`.

Все даты заказов в админке — UTC. Уведомления Telegram доставляются как минимум один раз: после аварийного завершения процесса одно сообщение может повториться. Неограниченные автоматические повторные списания/создания заказов iiko не выполняются.

Официальные контракты: [Т-Банк Init](https://developer.tbank.ru/eacq/api/init), [подпись запросов](https://developer.tbank.ru/eacq/intro/developer/token), [уведомления](https://developer.tbank.ru/eacq/intro/developer/notification/), [iiko API](https://api-ru.iiko.services/docs).
