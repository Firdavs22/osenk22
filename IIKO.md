# Подключение iiko

В этой версии реализован адаптер iiko Cloud API: авторизация v2, чтение справочников, импорт внешнего меню, сопоставление блюд и передача принятых заказов. Проверен на имитации API; реальная касса ресторана ещё не подключена. Наличие iikoПроф само по себе не подтверждает доступ к API — условия подключения организации уточняются у вашего партнёра iiko.

## Доступы

1. Зарегистрировать приложение в [портале разработчиков iiko](https://public-api.iikoweb.ru/portal): получить appId и clientSecret.
2. В iikoWeb ресторана выпустить API key с доступом к организациям, справочникам, доставкам и созданию заказов.
3. В /admin/integrations сохранить значения. Используется POST /api/v2/access_token с apiKey, appId, clientSecret; старый apiLogin не используется.
4. Нажать «Проверить доступ и прочитать справочники». Скопировать UUID организации, сохранить и повторить проверку для терминалов, типов оплаты и номенклатуры.
5. Указать терминальную группу. Для платной доставки выбрать UUID отдельной услуги доставки. Для оплаченных онлайн заказов выбрать UUID внешне проводимого типа Card.
6. Для импорта выберите ID внешнего меню и при необходимости UUID ценовой категории. Кнопка «Проверить доступ и прочитать справочники» также показывает externalMenus и priceCategories.
7. Нажмите «Загрузить меню — предпросмотр», проверьте изменения и нажмите «Применить импорт». UUID блюд и размеров сохраняются автоматически. Если товар создаётся вручную, эти UUID заполняются в его карточке.

Секреты вводятся только в админке вашего HTTPS-сайта; не отправляйте их в чат/GitHub. Они шифруются в базе; ключ хранится в DATA_DIR/integrations.key.

## Что передаётся

После перевода заказа в статус «Принят» создаётся задача. Онлайн-заказ нельзя принять, пока банк не подтвердит оплату. Передаются постоянный UUID заказа, позиции/количество/цены, телефон, имя однократного покупателя, комментарий, доставка либо самовывоз. Наличная оплата остаётся неоплаченной. Для подтверждённой онлайн-оплаты передаётся isProcessedExternally=true.

Платная доставка включается отдельной позицией для совпадения суммы. Включён checkStopList=true. Успешная отправка HTTP-запроса ещё не означает получение заказа кассой: сервис проверяет /api/1/deliveries/by_id и creationStatus для того же UUID.

Если ответ создания потерян, повторные попытки только читают тот же UUID, а не создают ещё один заказ. Через 60 попыток автоматическая проверка прекращается, оператор должен сверить iiko. В админке можно возобновить проверку, но нельзя вслепую повторить создание. После подтверждённой ошибки заказ обрабатывается вручную; состояние видно в «Интеграциях».

## Ограничения

- Каталог загружается по кнопке из внешнего меню iiko API версии 2. Постоянная синхронизация по расписанию и стоп-листы на витрине не реализованы. Стоп-лист проверяет iiko в момент передачи заказа; отказ обрабатывает сотрудник.
- Поддержаны обычные блюда с количеством и необязательным размером. Составные блюда, комбо и обязательные модификаторы требуют расширения адаптера и теста.
- Доставка использует address.type=city, line1, до 250 символов. Организация должна поддерживать формат (8.7.6+), что подтверждается настройкой в админке. Legacy-адреса требуют доработки/сопоставления улиц; самовывоз доступен независимо от формата.
- Статусы приготовления/курьера из iiko не импортируются. Смена или отмена локального статуса не меняет уже созданный заказ iiko. Его нужно также отменять/корректировать в iiko.
- Касса, чеки, налоги и внешняя оплата настраиваются с интегратором ресторана. Проверьте отсутствие двойной фискализации и выдачу закрывающего чека до запуска. Возврат денег через банк не заменяет отмену в iiko.
- Одна организация и одна терминальная группа; один веб-процесс и сервер.

## Приёмочный тест на вашей кассе

1. Сопоставить реальные блюда и размер. Согласовать тест с сотрудником, пометить комментарий «Тест интеграции — не готовить».
2. Оформить самовывоз с оплатой при получении, принять в админке. Сверить UUID, состав, количество, сумму, клиента и неоплаченное состояние в iikoFront.
3. Повторить с доставкой, проверить адрес и отдельную стоимость доставки.
4. Проверить стоп-лист, неверное сопоставление и недоступность iikoFront: отказ/ожидание должны быть видны, дубликата быть не должно.
5. После приёмки Т-Банка повторить с онлайн-оплатой и проверить внешнюю оплату, чеки и возврат совместно с интегратором.
6. Перезапустить веб-сервис во время ожидания ответа; проверить, что UUID остался прежним и второй заказ не появился.

Источники: [спецификация iiko API](https://api-ru.iiko.services/docs), [переход на авторизацию v2](https://iiko.ru/news/perehod-na-novuyu-shemu-avtorizaczii-v-api/).


## Импорт каталога

Подготовьте в iiko отдельное внешнее меню для сайта. В него должны входить только позиции, которые вы продаёте онлайн. Нужна цена именно выбранной организации; цена другой организации не подставляется.

Импорт создаёт категории и карточки для каждого сочетания UUID блюда и размера. Новые позиции скрыты до проверки состава и публикации сотрудником. Из iiko переносятся название, описание, вес, цена и публичные метки. Описание и сведения об аллергенах не заменяют проверенный состав: поле состава заполняется отдельно. Повторный импорт обновляет название, категорию, цену и вес, сохраняя вручную заполненные состав, описание, теги и фото. При одинаковом UUID/размере дубли не создаются.

Исчезнувшие из выбранного меню и неподдерживаемые ранее импортированные позиции скрываются при применении; в предпросмотре указано их число. Карточки и история заказов не удаляются. Скрытые в iiko товары снимаются с продажи, но повторный импорт сам не публикует скрытую карточку. Независимые товары магазина не изменяются. Пустой либо неподдерживаемый формат меню отклоняется, массовое скрытие из-за пустого ответа API не выполняется.

Перед применением виден предпросмотр, действующий 30 минут. Если за это время каталог или выбранное меню изменятся, загрузку нужно повторить. Применение атомарно; повторная отправка той же формы не дублирует импорт. Изменения на стороне iiko не выполняются.

Фотографии с управляемого CDN, указанного в спецификации iiko (`https://<число>.selcdn.ru/...`), ставятся в фоновую очередь. Загрузка ограничена 5 МБ и проверяется тем же обработчиком изображений, что и ручная загрузка; произвольные адреса, редиректы и локальные IP не загружаются. Другой источник фото отмечается в предпросмотре — загрузите такой снимок вручную. Текущее фото не перезаписывается. Прогресс и ошибки видны в «Интеграциях». Веб-сервис должен работать для обработки очереди. После трёх ошибок доступен повтор через новый импорт.

Комбо, составные блюда, обязательные или выбранные по умолчанию модификаторы, маркируемые товары, открытые/нулевые цены и категории с расписаниями не импортируются. Явно необязательные добавки без значений по умолчанию опускаются с предупреждением. Разрешение дробного количества само по себе не блокирует блюдо: сайт заказывает только целые порции. Меню с общим расписанием отклоняется. Для таких позиций нужно расширение модели заказа. Это осознанное ограничение: карточка не должна позволять оформить заказ, который касса не сможет принять.

## Что запросить у партнёра iiko

«Нужно подключить сайт заказа к актуальному iiko Cloud API. Нужны API key организации с правами чтения меню/справочников и работы с доставками, зарегистрированное приложение (appId и clientSecret), внешнее меню для сайта, ID организации и терминальной группы. Для меню — ID внешнего меню и используемой ценовой категории. Для заказов — тип внешней оплаты и услуга доставки. Проверьте возможность доступа по нашему тарифу и права приложения».

API key и clientSecret вводятся в закрытой админке, а не публикуются в переписке. UUID организации/терминала/меню/ценовых категорий можно получить через кнопку чтения справочников после выдачи ключей. Для одного только импорта передача заказов в iiko может оставаться выключенной; терминальная группа понадобится именно для отправки заказов.
