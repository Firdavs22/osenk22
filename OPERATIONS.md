# Заказы, сотрудники и смена меню

## Обновление VPS

Выполняйте по очереди после проверки `git status --short` из `/opt/sushi-bot`. При ошибке остановитесь; если службы уже остановлены, запустите их обратно перед разбором. `.env`, база, ключи и фото сохраняются.

```bash
cd /opt/sushi-bot
sudo systemctl stop sushi-web sushi-bot
sudo -u sushi .venv/bin/python -m app.manage backup
git pull --ff-only origin feature/online-store
sudo -u sushi .venv/bin/python -m app.manage init
sudo systemctl start sushi-web sushi-bot
sudo systemctl status sushi-web sushi-bot --no-pager
```

## Канбан и автопринятие

В «Заказах» колонки показывают статусы. В каждой колонке до 30 карточек на странице, счётчик показывает общее количество. Внизу — переход между страницами. Фильтр оставляет одну колонку. Доска обновляется раз в 10 секунд; во время просмотра подробностей обновление приостановлено. Карточка открывает окно с составом, суммами, покупателем, адресом, оплатой и кнопками следующего статуса. Без JavaScript доступна обычная страница заказа.

Настройка «Автоматически принимать новые заказы» включена при первом обновлении с этой функцией. Её можно выключить в «Настройках»; последующие обновления сохраняют выбор. Существующие заказы не меняются. Заказы с оплатой при получении принимаются после подтверждения покупателем, онлайн-заказы — после подтверждённого платежа банка. Неоплаченные, отменённые и завершённые заказы не переводятся автоматически. Принятый заказ ставится в очередь iiko, если передача включена. Статус «Принят» на сайте не означает подтверждение кассой: результат отправки смотрите в «Интеграциях». Для переданных заказов включена обратная проверка статусов iiko; подробности ниже.

## Ещё один сотрудник Telegram

Попросите сотрудника открыть бота магазина, отправить `/start`, затем `/id`. Подставьте его числовой ID:

```bash
sudo -u sushi .venv/bin/python -m app.manage telegram-admin-add --id 123456789
```

Команда добавляет получателя уведомлений, сохраняет прежних сотрудников, токен и остальные настройки. Повторное добавление не создаёт дубль. Секреты не печатаются. Веб-логин администратора эта команда не создаёт. Тот же список редактируется через «Интеграции → Telegram → ID администраторов / чатов». Если Telegram отключён, добавление ID его не включает.

## Список внешних меню iiko и переключение

```bash
sudo -u sushi .venv/bin/python -m app.manage iiko-menus
```

Команда вызывает `POST /api/2/menu` с сохранёнными доступами и выводит только названия/ID доступных внешних меню и ценовых категорий. Если нужного меню нет, проверьте его сохранение и доступность для интеграции «Сайт» в настройках Cloud API iikoWeb. API-ключи в чат не отправляйте.

Подставьте ID из списка вместо `12345`. Сначала получите предпросмотр:

```bash
sudo -u sushi .venv/bin/python -m app.manage iiko-menu --menu-id 12345
```

После проверки цен и количества изменений:

```bash
sudo -u sushi .venv/bin/python -m app.manage backup
sudo -u sushi .venv/bin/python -m app.manage iiko-menu --menu-id 12345 --apply
```

Команда запрашивает `/api/2/menu/by_id`, сохраняет действующую организацию и ценовую категорию. Если для нового меню нужна другая категория, добавьте `--price-category UUID` к обоим вызовам. Для базовой используйте именно значение, которое API вернул для вашей интеграции; автоматически сбрасывать его не нужно.

Предпросмотр не меняет настройки или каталог. Применение повторно читает актуальное меню; обновление карточек и смена ID выполняются в одной транзакции. Общие блюда сопоставляются по UUID/размеру, сохраняя ручной состав, фото и видимость. Отсутствующие позиции прежнего меню iiko скрываются. Ручные товары не удаляются. Новые блюда создаются скрытыми: проверьте состав и опубликуйте их массово в «Меню и товары». Пустой ответ не заменяет меню. Переключение между организациями этим способом запрещено. Уже оформленные заказы сохраняют прежние цены и UUID.

Расписание синхронизации сохраняется и далее использует новое меню; уже начатая загрузка старого меню не может записать результат после переключения. Если цена `null` или API отклоняет ценовую категорию, сначала исправьте источник цен в iikoWeb: команда не подставляет выдуманную цену.

## Повторные заказы и быстрые действия

Покупатель один раз подтверждает собственный номер через контакт Telegram/MAX. Переход по ссылке «Личный кабинет» повторно открывает историю без запроса номера; следующие заказы с этим телефоном привязываются автоматически и получают уведомления. Вход не включает отключённые уведомления: для этого есть отдельная кнопка. `/logout` удаляет привязку и требует нового подтверждения. Обычная подписка на один заказ по ссылке не подтверждает владение телефоном и не подключает все будущие заказы.

Карточка канбана показывает количество единиц блюд и общее количество заказов с тем же нормализованным телефоном (включая текущий и отменённые). Кнопка проводит заказ по следующему этапу; неоплаченные онлайн-заказы защищены. «Подробнее» открывает состав и адрес. Счётчик в меню админки показывает новые заказы.

Включите браузерные уведомления кнопкой внизу меню админки и разрешите их в браузере. Они работают на HTTPS, пока хотя бы одна вкладка админки открыта. Фоновая вкладка тоже проверяет заказы; браузер может замедлять её таймер. При закрытом браузере уведомлений нет — для этого остаётся Telegram сотрудников. Уведомление не содержит имя, телефон или адрес покупателя. Повторы между вкладками исключаются через Web Locks там, где браузер их поддерживает. Разрешение и выключатель относятся к этому браузеру. После выхода из админки проверка прекращается.

Во внешнем меню v2 разделы приходят плоским списком `itemCategories`: товары привязываются к категории, внутри которой API их прислал. Дерево групп iikoOffice — другой справочник. Проверены несколько категорий, скрытая группа, перенос блюда и повторный импорт; диагностика теперь включает ID, название, iikoGroupId и количество блюд каждого раздела. Названия категорий сопоставляются без различий регистра/лишних пробелов. Пустые категории скрыты на витрине. Дубли тегов убираются при отображении без удаления блюд, полоса прокрутки скрыта, сама прокрутка сохранена.

Приветствие обновлено в Telegram/MAX, описание профиля Telegram обновляется при запуске sushi-bot. При недоступности метода описания бот продолжает принимать заказы. Обновление не изменяет опубликованное описание профиля в кабинете MAX.

Горизонтальные списки категорий, тегов и канбан можно перетаскивать мышью. Колёсико над списком листает его вбок; на границе снова прокручивает страницу. Свайп телефона и горизонтальные жесты тачпада остаются нативными. Для тегов/категорий доступны клавиши ←/→, Home/End и Enter. Перетаскивание не нажимает кнопки, канбан не заменяется обновлением во время жеста.


## Аналитика, UTM и оформление

В «Обзоре» есть сводка за 30 дней, в «Аналитике» — период до 366 дней (границы по Москве), валюта, канал заказа и первый/последний рекламный переход. Отдельно считаются сумма всех оформленных заказов, выполненные, их средний чек и подтверждённая онлайн-оплата. Выполнение не подтверждает получение наличных. Возвраты отмечены количеством; частичный возврат не входит в полностью оплаченные онлайн-заказы. Это отчёты по дате создания и текущему состоянию заказов, не бухгалтерская прибыль. Для прибыли нужны расходы и себестоимость.

UTM: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` — до 100 символов каждое. Первый и последний переход сохраняются на сервере под случайным идентификатором браузера; через 90 дней без рекламного перехода привязка истекает. Обычный визит не затирает рекламу. При оформлении заказа создаётся неизменяемый снимок меток, доступный в подробностях заказа и отчёте. Старые метки не восстанавливаются. Отдельные браузеры, домены apex/app и нативные чаты автоматически не объединяются. Данные iiko/телефоны не используются для скрытого склеивания визитов. Категория блюда фиксируется для новых позиций заказа; у старых показано отсутствие сохранённой категории.

В «Аналитике → Подключения и настройки» введите номер счётчика Метрики и включите его. В кабинете Метрики включите электронную коммерцию (`dataLayer`) и создайте JS-цели `product_view`, `add_to_cart`, `begin_checkout`, `order_created`, `payment_success`. Счётчик выключен по умолчанию; после включения загружается только с разрешения покупателя. Выбор меняется в подвале витрины. Без Вебвизора и передачи контактных полей. На странице заказа отчётный URL обезличен до `/order`, события доступны только браузеру, оформившему заказ. `purchase` — заказ с оплатой при получении либо подтверждённая онлайн-оплата; `payment_success` — только подтверждённая банком. В текущем браузере события дедуплицируются по номеру счётчика, заказа и типу. Блокировщики/удаление localStorage могут влиять на внешнюю статистику; внутренняя сводка берётся из базы. Настройка сторонних счётчиков кроме Метрики в этот выпуск не включена.

Обновлён встроенный текст политики. Если магазин использует собственный текст политики в настройках, он по-прежнему заменяет встроенный целиком.

«Оформление сайта → Акции и первый экран»: картинка справа, фон на всю ширину или готовый баннер целиком без обрезки. Можно загрузить отдельный файл для телефона, выбрать положение и цвета текста/кнопки, затемнение фона, скрыть надписи/кнопку, порядок и активность. Оба файла вместе — до 5 МБ (лимит запроса 6 МБ). Для режима фона готовьте картинку без встроенного текста, учитывая обрезку краёв; для готового изображения с надписями используйте режим без обрезки. Кнопка ведёт в каталог или категорию. Изменения не загружают пример пользователя на рабочую витрину автоматически.

## Получение статусов iiko

Встроенный worker `sushi-web` читает `/api/1/deliveries/by_id` для заказов, создание которых подтверждено (`iiko_jobs.state=sent`). Включено по умолчанию, переключатель — «Аналитика → Подключения и настройки». До 20 заказов за проход, группировка по сохранённым настройкам организации, интервал от 60 секунд; при сбое — от 120 секунд. Очередь может увеличить задержку. Используются UUID и настройки именно переданного заказа. API сверено с официальной схемой https://api-ru.iiko.services/api-docs/docs.

- `WaitCooking`, `ReadyForCooking` → принят;
- `CookingStarted` → готовится;
- `CookingCompleted`, `Waiting`, `OnWay` → готов / передан курьеру;
- `Delivered`, `Closed` → выполнен;
- `Cancelled` → отменён.

Переходы только вперёд; завершённые/отменённые локально не открываются повторно. Разрешён пропуск промежуточных этапов: при получении готовности отправляется только одно уведомление о готовности. Используются существующие очереди Telegram/MAX и обновление страницы заказа/канбана. Неизвестный статус, чужой UUID, отказ API или отсутствие подтверждённой онлайн-оплаты не меняют заказ; диагностика видна в «Интеграциях» и подробностях заказа. «Проверить» планирует повторное чтение, не создаёт ещё один заказ. Гарантированный срок доступности заказа через этот метод iiko — последние 7 дней; старые незавершённые заказы могут требовать ручной проверки. Автоматического возврата денег и обратной отправки ручной смены статуса в iiko нет.

Обновление VPS: остановить `sushi-web sushi-bot`, создать резервную копию (`sudo -u sushi .venv/bin/python -m app.manage backup`), получить ветку `feature/online-store`, выполнить `sudo -u sushi .venv/bin/python -m app.manage init`, запустить оба сервиса. Миграции добавляют поля/таблицы, не удаляя каталог и заказы. После обновления сделайте Ctrl+F5. Подключение реального счётчика и изменение состояния реального заказа в iiko проверяются на VPS отдельно.
