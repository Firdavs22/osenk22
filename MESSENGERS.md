# Telegram и MAX

Один каталог, фотографии, цены и наличие берутся из базы сайта. Импорт iiko обновляет ту же базу; опубликованные товары доступны в мессенджерах. Скрытые блюда не появляются в меню.

## Обновление работающего VPS

Из `/opt/sushi-bot` сначала проверьте `git status --short`. Если есть ваши изменения кода, сохраните их перед обновлением. `.env`, база и изображения исключены из Git и остаются на сервере.

Выполняйте по очереди, продолжая только после успешного завершения команды:

```bash
cd /opt/sushi-bot
sudo systemctl stop sushi-web sushi-bot
sudo -u sushi .venv/bin/python -m app.manage backup
git pull --ff-only origin feature/online-store
sudo -u sushi .venv/bin/python -m app.manage init
sudo systemctl start sushi-web sushi-bot
sudo systemctl status sushi-web sushi-bot --no-pager
```

Новых Python-зависимостей нет. `init` добавляет таблицы, не сбрасывает каталог, настройки или заказы. При ошибке загрузки кода запустите остановленные службы и разберите ошибку до повторного обновления. Не запускайте `setup` заново и не меняйте ключ шифрования интеграций.

Домен и конфигурация Nginx остаются прежними. Для мини-приложений в `.env` должно быть `COOKIE_SECURE=true`, сайт должен открываться по HTTPS. После изменения `.env` перезапустите обе службы. Один веб-worker обязателен, как в поставляемом systemd unit.

## Telegram

В админке → **Подключения → Telegram** укажите адрес `https://app.osenkusna.ru`, включите мини-приложение и сохраните. Действующий токен повторно вводить не нужно. Бот применит изменение адреса за 15 секунд; при необходимости выполните `sudo systemctl restart sushi-bot`.

Отправьте `/start` в личном чате. Кнопка **Открыть меню с фото** и нижняя кнопка меню открывают `https://app.osenkusna.ru/mini/telegram`. Заказ в чате также доступен: категории, карточки, корзина и оформление.

Бот редактирует свой предыдущий экран. При смене текста на фотографию или показе клавиатуры телефона создаёт замену и удаляет старый экран, если Telegram разрешает удаление. Исторические сообщения до обновления, сообщения покупателя и отдельные уведомления о заказах не удаляются. Очень длинный текст разбивается на несколько сообщений.

## MAX: заказ в чате и отдельное мини-приложение

Без доступа к платформе MAX оставьте интеграцию выключенной. Публичный каталог `/mini/max` уже готов, но это само по себе не регистрирует бота.

После получения доступа:

1. Создайте бота в платформе MAX для партнёров и получите токен.
2. В админке сайта → **Подключения → MAX** сохраните токен, адрес `https://app.osenkusna.ru` и включите MAX.
3. Нажмите **Проверить токен MAX**, затем **Зарегистрировать webhook MAX**. Секрет webhook генерируется автоматически и хранится зашифрованным вместе с токеном. Входящие запросы приходят на `https://app.osenkusna.ru/api/max/webhook`.
4. Для дополнительного мини-приложения привяжите в кабинете MAX URL `https://app.osenkusna.ru/mini/max` и включите на сайте флажок «Мини-приложение уже привязано к боту в кабинете MAX». Отдельная кнопка «Мини-приложение» использует `open_app`; без привязки она открывает сайт ссылкой. Основная кнопка «Меню в чате» всегда показывает категории в сообщении. После обновления отправьте `/menu`, чтобы заменить старые кнопки.
5. Начните личный чат с ботом и проверьте меню, «О магазине», корзину, оформление и оплату. Ответы при навигации редактируются. Бот не обслуживает групповые чаты.

MAX обрабатывается службой `sushi-web`, отдельный сервис не нужен. События webhook сохраняются в очередь с защитой от повторной доставки. Текст до 500 символов и проверенный контакт сохраняются зашифрованными для обработки оформления; после успешной обработки содержимое события очищается. Полный профиль и имена отправителя из webhook не сохраняются. Черновик оформления зашифрован и действует час. Результаты обработки, необходимые для защиты от повторных изменений корзины, также зашифрованы и удаляются через семь дней. История заказов не удаляется. Ошибки событий доступны в разделе MAX, ошибки уведомлений — в разделе «Уведомления». При неизвестном результате отправки автоматический повтор останавливается; перед ручным повтором проверьте чат.

В чате: `/menu` → категория → блюдо с фотографией и составом → «В корзину» → `/cart` → доставка/самовывоз → имя → телефон → адрес для доставки → комментарий → способ оплаты → явное подтверждение. Расчёт использует настройки сайта: скидку на самовывоз, минимальную сумму, районы и стоимость доставки. Сейчас в этом сценарии доступна оплата наличными или картой при получении (если включена магазином); онлайн-оплата остаётся в отдельном мини-приложении. Корзины MAX, Telegram и сайта независимы.

Заказ получает источник «MAX · чат», сохраняется в общей админке и передаётся в iiko после принятия по существующим настройкам. Ввод телефона для заказа не даёт доступа к чужой истории. Свои заказы из чата покупатель видит через `/orders` без дополнительного входа; заказы сайта с тем же номером становятся доступны только после подтверждения собственного контакта через `/account`. Подтверждения заказов, история и статусы отправляются отдельными сообщениями, которые навигация не перезаписывает. `/stopupdates` отключает статусы, повторное подтверждение контакта включает их снова. После перезапуска корзина и очередь сообщений сохраняются. Повтор подтверждения не создаёт второй заказ; при изменившихся ценах или наличии нужно заново проверить итог.

API MAX требует доверенного TLS-соединения. Если сервер не доверяет цепочке сертификатов MAX, установите необходимые корневые сертификаты согласно официальной документации MAX либо укажите в `.env` абсолютный путь `MAX_CA_BUNDLE=/opt/sushi-bot/data/max-ca.pem` к проверенному PEM-файлу корневых CA. Файл должен читаться пользователем `sushi`; затем перезапустите `sushi-web`. Не отключайте проверку сертификатов. Токен отправляется только в заголовке авторизации, не в URL.

При смене токена или домена повторите проверку и регистрацию webhook. Удалите старую подписку в кабинете MAX, если изменился домен. Флажок включения без регистрации webhook ещё не означает, что события поступают.

## Корзины, заказы и проверка перед запуском

Мини-приложения используют **гостевое оформление** сайта: пользователь вводит контактные данные сам. Само открытие мини-приложения не создаёт личный кабинет, не подтверждает Telegram/MAX ID и не доверяет присланному `initDataUnsafe`. Личный кабинет подключается отдельно в боте по подтверждённому номеру. Корзина в чате Telegram и корзина мини-приложения отдельные. В разных браузерах и мессенджерах корзины также могут различаться. Вход администратора отделён от гостевой сессии и запрещён во фрейме.

После оформления страница заказа проверяет статус и оплату каждые 10 секунд, пока вкладка открыта. Изменение статуса или готовность ссылки на оплату обновляет страницу. При потере сети есть повторная проверка и ручная кнопка. Это не push-уведомление после закрытия сайта.

Покупатель сайта или мини-приложения может нажать **«Получать статус в Telegram»**, перейти в бота и нажать «Запустить». Одноразовая ссылка действует 10 минут; после запуска подписка связывает только этот заказ с Telegram-чатом. Имя, телефон и адрес в ссылке не передаются. Смена статуса в админке ставит сообщение покупателю в очередь. Отключение — кнопкой на странице заказа или командой `/stopupdates` в боте (все подписки этого чата). Это отдельное согласованное подключение, а не автоматическая идентификация при открытии Mini App. Смена бота не переносит подписчиков в другого бота.

Кнопка подписки появляется после успешного старта `sushi-bot` или проверки Telegram в админке: имя бота берётся из `getMe`. Telegram должен быть включён. Для получения сообщений процесс `sushi-bot` обязан работать. Статусы из кассы iiko пока не синхронизируются обратно — сотрудник меняет их в админке сайта.

## Если сотрудники не получают уведомления

Откройте **Админка → Уведомления**. Там видны получатели, имя бота, свежесть сигнала процесса отправки и последние 100 сообщений, включая успешные. «Отправлено» означает подтверждение Telegram, а не прочтение. Сообщения при неправильном ID, блокировке бота, сетевой ошибке и ограничении частоты имеют понятную причину. После исправления получателя недоставленное сообщение можно повторить.

В **Подключениях → Telegram** укажите числовые ID сотрудников. Каждый должен первым отправить `/start` именно этому боту; `/id` покажет его ID. Проверьте на VPS:

```bash
sudo systemctl status sushi-bot --no-pager -l
sudo journalctl -u sushi-bot -n 50 --no-pager
```

Не публикуйте журнал без проверки на секреты и контакты. Не запускайте одновременно ещё одну копию того же бота на компьютере. Работа сайта `sushi-web` не подтверждает работу отдельного процесса Telegram. Проверка токена проверяет только `getMe`, не доставку сообщения сотруднику.

Новые заказы без настроенных получателей больше не помечаются как уведомлённые: после настройки они ставятся в очередь один раз, если заказ ещё не завершён/отменён (для онлайн-оплаты — после подтверждения банка). Ранее обработанные старой версией заказы автоматически заново не рассылаются. Изменение ID получателя не перенаправляет уже поставленные сообщения на другой ID.

Для iiko самовывоз передаётся как `DeliveryByClient` без адреса курьерской доставки. Для доставки передаются имя, телефон, комментарий и `deliveryPoint.address.line1`. Галочка City в нашем интерфейсе должна соответствовать реальной настройке организации iiko. Она не переключает формат адресов на стороне iiko.

Заказы появляются в общей админке с источником «Telegram Mini App» или «MAX Mini App». Это метка канала, а не подтверждённая личность покупателя. Уведомления сотрудникам идут через существующий Telegram-канал. Покупатель следит за заказом на странице заказа или подключает личный кабинет в Telegram/MAX и получает отдельные сообщения о статусах. Онлайн-оплата открывается во внешнем окне, результат проверяется сервером по прежней схеме.

Перед приёмом заказов пройдите на телефоне: открытие меню → карточка с фото → добавление/удаление → оформление → оплата → возврат на страницу заказа. Проверьте получение уведомления сотрудником и отсутствие второго заказа при повторном нажатии. При блокировке сторонних cookie браузером используйте обычный сайт. Реальные клиенты Telegram/MAX и эквайринг требуют такой проверки с вашими доступами; автоматические тесты используют имитацию API.

Официальные инструкции: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [мини-приложения MAX](https://dev.max.ru/docs/webapps/introduction), [webhook MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions).


## Личный кабинет в Telegram и MAX

После заказа сайт предлагает открыть личный кабинет в Telegram или MAX. Это обычные ссылки `?start=account`, без телефона, адреса и секретного URL заказа. MAX показывается после проверки токена и регистрации webhook. В боте есть «Личный кабинет», «Мои заказы», команды `/account`, `/orders`, `/stopupdates` и `/logout`.

Покупатель нажимает «Поделиться своим номером» и подтверждает передачу контакта. Telegram проверяет соответствие `contact.user_id` отправителю; пересланные контакты отклоняются. MAX дополнительно проверяет HMAC-SHA256 поля `vcf_info` с токеном бота и соответствие `max_info.user_id` отправителю. Чужой контакт, просто введённый телефон, неподписанный контакт и истёкший запрос не дают доступа к заказам. Запрос действует 10 минут. Если телефон мессенджера отличается от номера заказа, используйте приватную страницу заказа или обратитесь в магазин; SMS-подтверждение другого номера не подключено.

В историю попадают существующие и будущие заказы с подтверждённым телефоном. Российские номера с 8, +7, пробелами и скобками сопоставляются. История доступна порциями по пять заказов с кнопкой «Ещё заказы». Исторические сообщения и уведомления не редактируются и не удаляются ботом при навигации. В MAX история выводится кратко: номер, блюда, сумма, получение, дата и статус. Новые заказы и изменения статуса автоматически попадают в отдельную устойчивую очередь и отправляются после перезапуска служб. Открытый сайт для этого не нужен. Повторно подтверждать номер перед каждым заказом не требуется.

`/stopupdates` выключает уведомления личного кабинета, сохраняя доступ к истории. `/account` и повторное подтверждение контакта включают их снова. `/logout` удаляет привязку кабинета, а не заказы или уже доставленные сообщения. Повторный вход восстанавливает историю по подтверждённому номеру. Для смены номера сначала нужен выход. Если номер уже привязан другому пользователю того же бота, автоматическая перепривязка запрещена: нужен разбор магазином. При смене токена MAX требуется повторный вход; привязки не переносятся между разными ботами.

Ранее выданные одноразовые Telegram-подписки на один заказ продолжают работать. Они не дают доступа ко всей истории по телефону. Для сайта поддержаны кабинеты обоих мессенджеров; если покупатель подключил оба, уведомления приходят в оба.

В админке → «Уведомления» есть отдельная таблица доставок личного кабинета. Неопределённая отправка MAX после сетевого таймаута не повторяется автоматически; проверьте чат перед ручным повтором. Отправка не означает прочтение. Статусы по-прежнему меняет сотрудник в админке сайта: обратной синхронизации статусов iiko нет.

## Ошибка MAX: unable to get local issuer certificate

Открытие `/mini/max` подтверждает работу сайта, но не соединение VPS с API бота. MAX требует сертификат Минцифры для `platform-api2.max.ru`. В проекте поддержано отдельное хранилище доверия **только для API MAX**, без изменения системного хранилища и без отключения TLS-проверки.

После обновления кода на VPS:

```bash
cd /opt/sushi-bot
sudo bash deploy/setup-max-ca.sh
sudo -u sushi .venv/bin/python -m app.max_check
```

Скрипт скачивает корневой и выпускающий PEM-сертификаты с официального `gu-st.ru`, проверяет срок и цепочку, проверяет TLS к MAX без токена, затем сохраняет `data/max-ca.pem`, прописывает `MAX_CA_BUNDLE` в `.env` и перезапускает `sushi-web`. Если скачивание, сертификаты или TLS не прошли проверку, настройка не применяется. Токен в командах и выводе не появляется. `app.max_check` выполняет только `GET /me`, без сообщений и регистрации webhook.

Если официальные URL сертификатов изменились, скачайте актуальные корневой и выпускающий сертификаты для Linux с https://www.gosuslugi.ru/crt и сформируйте PEM-файл по тому же пути; повторите проверку. Не используйте `curl -k` или `verify=False`. Обычный `curl` без `--cacert` может по-прежнему выдавать ошибку: системное доверие намеренно не меняется.

После успешной проверки в админке нажмите **«Проверить токен MAX»**, затем **«Зарегистрировать webhook MAX»**. Ссылка мини-приложения в кабинете MAX остаётся `https://app.osenkusna.ru/mini/max`. Флажок «Мини-приложение уже привязано» можно включить, когда оно действительно открывается в MAX.

Приёмочная проверка на телефоне: заказ на сайте → личный кабинет в боте → собственный контакт → заказ в истории → смена статуса в админке → уведомление → переходы по меню без исчезновения истории → второй заказ с тем же телефоном → уведомление без повторного входа. Локальные тесты используют имитацию API; реальное подключение на VPS проверяется после установки сертификата и обновления служб.

Источники: [API MAX](https://dev.max.ru/docs-api), [проверка контакта MAX](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard), [диплинки MAX](https://dev.max.ru/help/deeplinks), [контакты Telegram](https://core.telegram.org/bots/api#contact), [сертификаты Госуслуг](https://www.gosuslugi.ru/crt).
