# Telegram и MAX

Один каталог, фотографии, цены и наличие берутся из базы сайта. Импорт iiko обновляет ту же базу; опубликованные товары доступны в мессенджерах. Скрытые блюда не появляются в меню.

## Обновление работающего VPS

Из `/opt/sushi-bot` сначала проверьте `git status --short`. Если есть ваши изменения кода, сохраните их перед обновлением. `.env`, база и изображения исключены из Git и остаются на сервере.

Выполняйте по очереди, продолжая только после успешного завершения команды:

```bash
cd /opt/sushi-bot
sudo systemctl stop sushi-web sushi-bot
sudo -u sushi .venv/bin/python -m app.manage backup
git pull --ff-only origin feature/online-store
sudo -u sushi .venv/bin/python -m app.manage init
sudo systemctl start sushi-web sushi-bot
sudo systemctl status sushi-web sushi-bot --no-pager
```

Новых Python-зависимостей нет. `init` добавляет таблицы, не сбрасывает каталог, настройки или заказы. При ошибке загрузки кода запустите остановленные службы и разберите ошибку до повторного обновления. Не запускайте `setup` заново и не меняйте ключ шифрования интеграций.

Домен и конфигурация Nginx остаются прежними. Для мини-приложений в `.env` должно быть `COOKIE_SECURE=true`, сайт должен открываться по HTTPS. После изменения `.env` перезапустите обе службы. Один веб-worker обязателен, как в поставляемом systemd unit.

## Telegram

В админке → **Подключения → Telegram** укажите адрес `https://app.osenkusna.ru`, включите мини-приложение и сохраните. Действующий токен повторно вводить не нужно. Бот применит изменение адреса за 15 секунд; при необходимости выполните `sudo systemctl restart sushi-bot`.

Отправьте `/start` в личном чате. Кнопка **Открыть меню с фото** и нижняя кнопка меню открывают `https://app.osenkusna.ru/mini/telegram`. Заказ в чате также доступен: категории, карточки, корзина и оформление.

Бот редактирует свой предыдущий экран. При смене текста на фотографию или показе клавиатуры телефона создаёт замену и удаляет старый экран, если Telegram разрешает удаление. Исторические сообщения до обновления, сообщения покупателя и отдельные уведомления о заказах не удаляются. Очень длинный текст разбивается на несколько сообщений.

## MAX: подготовлено, нужен токен

Без доступа к платформе MAX оставьте интеграцию выключенной. Публичный каталог `/mini/max` уже готов, но это само по себе не регистрирует бота.

После получения доступа:

1. Создайте бота в платформе MAX для партнёров и получите токен.
2. В админке сайта → **Подключения → MAX** сохраните токен, адрес `https://app.osenkusna.ru` и включите MAX.
3. Нажмите **Проверить доступ**, затем **Подключить webhook**. Секрет webhook генерируется автоматически и хранится зашифрованным вместе с токеном. Входящие запросы приходят на `https://app.osenkusna.ru/api/max/webhook`.
4. В кабинете MAX привяжите к боту мини-приложение с URL `https://app.osenkusna.ru/mini/max`. После этого включите в админке сайта флажок «Мини-приложение уже привязано к боту в кабинете MAX». Кнопка будет использовать официальную ссылку запуска приложения. До привязки она открывает сайт обычной ссылкой.
5. Начните личный чат с ботом и проверьте меню, «О магазине», корзину, оформление и оплату. Ответы при навигации редактируются. Бот не обслуживает групповые чаты.

MAX обрабатывается службой `sushi-web`, отдельный сервис не нужен. События webhook сохраняются в очередь с защитой от повторной доставки. Текст сообщений, имена и телефоны из событий не сохраняются; обработанные события удаляются через семь дней. Ошибки доступны в разделе MAX. Если результат отправки сообщения неизвестен после сетевого таймаута, повторная отправка остановлена, чтобы не создавать дубликаты: покупатель может отправить новую команду.

API MAX требует доверенного TLS-соединения. Если сервер не доверяет цепочке сертификатов MAX, установите необходимые корневые сертификаты согласно официальной документации MAX либо укажите в `.env` абсолютный путь `MAX_CA_BUNDLE=/opt/sushi-bot/data/max-ca.pem` к проверенному PEM-файлу корневых CA. Файл должен читаться пользователем `sushi`; затем перезапустите `sushi-web`. Не отключайте проверку сертификатов. Токен отправляется только в заголовке авторизации, не в URL.

При смене токена или домена повторите проверку и регистрацию webhook. Удалите старую подписку в кабинете MAX, если изменился домен. Флажок включения без регистрации webhook ещё не означает, что события поступают.

## Корзины, заказы и проверка перед запуском

Мини-приложения используют **гостевое оформление** сайта: пользователь вводит контактные данные сам. Они не создают личный кабинет, не получают Telegram/MAX ID и не доверяют присланному `initDataUnsafe`. Корзина в чате Telegram и корзина мини-приложения отдельные. В разных браузерах и мессенджерах корзины также могут различаться. Вход администратора отделён от гостевой сессии и запрещён во фрейме.

После оформления страница заказа проверяет статус и оплату каждые 10 секунд, пока вкладка открыта. Изменение статуса или готовность ссылки на оплату обновляет страницу. При потере сети есть повторная проверка и ручная кнопка. Это не push-уведомление после закрытия сайта.

Покупатель сайта или мини-приложения может нажать **«Получать статус в Telegram»**, перейти в бота и нажать «Запустить». Одноразовая ссылка действует 10 минут; после запуска подписка связывает только этот заказ с Telegram-чатом. Имя, телефон и адрес в ссылке не передаются. Смена статуса в админке ставит сообщение покупателю в очередь. Отключение — кнопкой на странице заказа или командой `/stopupdates` в боте (все подписки этого чата). Это отдельное согласованное подключение, а не автоматическая идентификация при открытии Mini App. Смена бота не переносит подписчиков в другого бота.

Кнопка подписки появляется после успешного старта `sushi-bot` или проверки Telegram в админке: имя бота берётся из `getMe`. Telegram должен быть включён. Для получения сообщений процесс `sushi-bot` обязан работать. Статусы из кассы iiko пока не синхронизируются обратно — сотрудник меняет их в админке сайта.

## Если сотрудники не получают уведомления

Откройте **Админка → Уведомления**. Там видны получатели, имя бота, свежесть сигнала процесса отправки и последние 100 сообщений, включая успешные. «Отправлено» означает подтверждение Telegram, а не прочтение. Сообщения при неправильном ID, блокировке бота, сетевой ошибке и ограничении частоты имеют понятную причину. После исправления получателя недоставленное сообщение можно повторить.

В **Подключениях → Telegram** укажите числовые ID сотрудников. Каждый должен первым отправить `/start` именно этому боту; `/id` покажет его ID. Проверьте на VPS:

```bash
sudo systemctl status sushi-bot --no-pager -l
sudo journalctl -u sushi-bot -n 50 --no-pager
```

Не публикуйте журнал без проверки на секреты и контакты. Не запускайте одновременно ещё одну копию того же бота на компьютере. Работа сайта `sushi-web` не подтверждает работу отдельного процесса Telegram. Проверка токена проверяет только `getMe`, не доставку сообщения сотруднику.

Новые заказы без настроенных получателей больше не помечаются как уведомлённые: после настройки они ставятся в очередь один раз, если заказ ещё не завершён/отменён (для онлайн-оплаты — после подтверждения банка). Ранее обработанные старой версией заказы автоматически заново не рассылаются. Изменение ID получателя не перенаправляет уже поставленные сообщения на другой ID.

Для iiko самовывоз передаётся как `DeliveryByClient` без адреса курьерской доставки. Для доставки передаются имя, телефон, комментарий и `deliveryPoint.address.line1`. Галочка City в нашем интерфейсе должна соответствовать реальной настройке организации iiko. Она не переключает формат адресов на стороне iiko.

Заказы появляются в общей админке с источником «Telegram Mini App» или «MAX Mini App». Это метка канала, а не подтверждённая личность покупателя. Уведомления сотрудникам идут через существующий Telegram-канал. Покупатель следит за заказом на странице заказа; отдельные сообщения о статусе в MAX этой версией не отправляются. Онлайн-оплата открывается во внешнем окне, результат проверяется сервером по прежней схеме.

Перед приёмом заказов пройдите на телефоне: открытие меню → карточка с фото → добавление/удаление → оформление → оплата → возврат на страницу заказа. Проверьте получение уведомления сотрудником и отсутствие второго заказа при повторном нажатии. При блокировке сторонних cookie браузером используйте обычный сайт. Реальные клиенты Telegram/MAX и эквайринг требуют такой проверки с вашими доступами; автоматические тесты используют имитацию API.

Официальные инструкции: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [мини-приложения MAX](https://dev.max.ru/docs/webapps/introduction), [webhook MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions).
